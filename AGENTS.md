## Идентичность проекта

- Проект: MKK Scenario Game Tools.
- Техническое имя: `mkk_sgt`.
- Префикс сборки: `sgt`.
- Назначение: набор инструментов MKK для подготовки сценариев Arma 3.

## Текущее состояние проекта

- HEMTT: `name = "MKK Scenario Game Tools"`, `prefix = "sgt"`.
- Реализован addon `sgt_main` в `addons/main`.
- `sgt_main` создан на базе `extra/base`.
## Реализовано в `sgt_main`

- Дневниковое меню действий.
- Дневниковый список групп и юнитов.
- Служебные маркеры групп, техники, ящиков, строений и ботов.
- Сохранение и загрузка пользовательских маркеров в profileNamespace.
- Отметки высоты, подсветка позиции и тайминг.
- Clipboard-отчеты по пехоте, технике, условностям и брифингу.
- Вселение в юнита под курсором.

## Карта модулей

- `sgt_main`: текущий основной addon. Содержит CBA/XEH-каркас, состояние, дневниковое меню, marker helpers, отчеты, hotkey/display handlers и action вселения.

## Шаблоны кодирования

- SQF-функции добавлять как `addons/<module>/functions/fnc_name.sqf` и регистрировать в `XEH_PREP.hpp` соответствующего модуля.
- Для текущего модуля использовать `addons/main/functions/fnc_name.sqf` и `addons/main/XEH_PREP.hpp`.
- Сохранять CBA-структуру addon: `script_component.hpp`, `XEH_PREP.hpp`, XEH init-файлы, `CfgEventHandlers.hpp`, `config.cpp`.
- Использовать macros `FUNC`, `EFUNC`, `QFUNC`, `GVAR`, `QGVAR` вместо ручной сборки имен функций или переменных.
- Новые видимые строки помещать в `addons/main/stringtable.xml` с English и Russian.
- Новые localization keys называть `STR_MKK_SGT_*`.
- Не использовать новые `ptg_*`, `mkk_ptg_*`, `fnc_kbn_*`, `kbn_*`, `kaban_*` имена.
- Remote-callable функции добавлять только при необходимости; не открывать широкий remote execution без причины.
- Для настраиваемого поведения использовать CBA settings/keybind шаблоны. Значения настроек читать с безопасными дефолтами.
- В SQF избегать `if !(x isEqualTo y)`; использовать прямые формы вроде `x isNotEqualTo y`.

## Runtime и locality

- Клиентские UI, diary, map, camera, HUD и display handlers держать за `hasInterface`.
- Серверные проверки полномочий и создание/удаление объектов держать за `isServer` или отдельный серверный поток, если такая система будет добавлена.
- Текущее удаление `deleteAllMarkers` удаляет только markers SGT, не игровые объекты.
- Создание, удаление и cleanup игровых объектов еще не реализованы; при добавлении учитывать locality.

## Предпочтительная проверка

Запускать минимальную релевантную проверку. Не запускать широкие build/test-команды, если задача этого не требует или пользователь не попросил.

- Для новых SQF-функций проверить, что файл, `XEH_PREP.hpp` и места вызова используют одно имя функции.
- Для локализации проверить, что каждый новый `STR_MKK_SGT_*` key имеет English и Russian.
- Для UI/HUD изменений проверить, что IDC/layer names уникальны внутри затронутого dialog/title.
- Для camera/tracking/HUD проверить, что клиентская логика защищена `hasInterface` и cleanup удаляет runtime-состояние.
- Для spawn/delete/rearm проверить, что действия с объектами выполняются на машине-владельце объекта или через явный серверный поток.
